# RED 1.7.0 Release Notes

**Release date:** 27 August 2026

RED 1.7.0 consolidates the customer-facing changes published as RED 1.6.1, 1.6.2 and 1.6.3 into one public GitHub release. It includes ChatGPT connector metadata, Claude connector and batch-workflow improvements, and the final metadata changes required for Anthropic’s connector review.

## RED 1.6.1 — ChatGPT connector metadata

**Released:** 20 August 2026

RED 1.6.1 prepares the production RED connector for submission to the ChatGPT plugin directory.

### ChatGPT tool annotations

RED’s 159 production tools now include the MCP safety annotations required by ChatGPT.

The annotations help ChatGPT distinguish between:

- Read-only tools that retrieve information
- Tools that create or update Big Red Cloud data
- Destructive actions, including deletions
- Open-world actions, including sending emails

These classifications support appropriate confirmation behaviour and help ChatGPT understand the potential effect of each action before selecting a tool.

### OpenAI domain verification

RED now provides the secure domain-verification endpoint required to demonstrate control of the production MCP domain during the ChatGPT submission process.

The verification endpoint is hosted on RED’s production domain and returns the OpenAI-provided verification token in the required format.

### What changed for users?

There are no changes to existing accounting calculations, records or workflows in this release.

## RED 1.6.2 — Claude connector and batch workflow improvements

**Released:** 25 August 2026

This release prepares the production connector for submission to Anthropic’s Connectors Directory and improves the safety and reliability of batch accounting workflows in both Claude and ChatGPT.

### Improved tool names and metadata

All 159 production tools now include clear, human-readable titles.

These titles are published both in the standard MCP tool metadata and in the annotation format used by Anthropic. This allows Claude’s Connectors Directory to display and classify RED’s tools correctly.

Existing read-only, write, destructive and open-world safety classifications remain unchanged.

### Analysed cash-receipt fix

RED now preserves cash-receipt analysis entries when VAT on Cash Receipts is disabled for a company.

Previously, a valid analysis line could be removed before the request reached Big Red Cloud, causing the transaction to be rejected because the total had not been analyzed.

The corrected workflow:

- Preserves structured analysis entries
- Builds an analysis entry from supplied analysis fields
- Removes only VAT-specific fields when VAT on Cash Receipts is disabled
- Keeps VAT entries conditional on the company’s VAT settings
- Reconciles analysed receipt values to the transaction total

The shared fix also applies to supported cash-receipt update and batch workflows.

### Nested batch sales documents

Batch sales invoices and sales credit notes now preserve complete nested product and analysis lines.

RED no longer replaces supplied product, VAT, analysis or note values with blank identifiers, zero values or generic placeholders when a valid nested document is provided.

The corrected payload handling preserves:

- Product IDs and codes
- Quantities and unit prices
- VAT rates and percentages
- Sales analysis categories
- Transaction notes
- Net, VAT and gross totals

### Accurate batch results

RED now correctly reads Big Red Cloud’s batch-response envelope.

Batch responses clearly report:

- Whether the complete batch succeeded
- Whether only part of the batch succeeded
- Successful and failed item counts
- Details of failed items
- Created records

This prevents successful transactions from being incorrectly reported as failures and reduces the risk of users retrying transactions that were already created.

### Typed batch-purchase schema

The batch-purchase tool now publishes a complete, strongly typed input contract.

Claude and ChatGPT can identify the required supplier, transaction date, purchase-analysis, net amount and VAT fields directly from the tool schema. RED continues to calculate and reconcile the final purchase totals.

### Strongly typed public batch tools

The remaining public batch tools no longer expose unspecified, free-form item objects.

Strict schemas are now available for batch workflows involving:

- Quotes
- Sales invoices
- Sales credit notes
- Sales entries
- Purchases
- Cash receipts
- Cash payments
- Bank payments
- Products
- Customers
- Suppliers
- Sales representatives

The schemas identify required fields, supported accounting modes and incompatible field combinations before a request reaches Big Red Cloud.

Depending on the workflow, RED validates:

- Customer, supplier, product, bank, VAT and analysis identifiers
- Required transaction dates
- Positive amounts and identifiers
- Reconciled net, VAT and gross totals
- Correct credit-note signs
- Customer and supplier code limits
- Receipt and payment modes
- Unexpected or unsupported fields

### Compatibility information

Public batch requests now use the canonical structure:

```json
{ "opCode": 1, "item": { ... } }
```

Users with an existing custom RED connector should refresh or reconnect it so Claude or ChatGPT receives the latest tool metadata.

Individual non-batch accounting tools are unaffected.

### Testing and verification

Version 1.6.2 was validated through:

- TypeScript type checking
- Batch payload and schema regression tests
- Transaction, routing and confirmation tests
- Registration checks across all 159 production tools
- Staging deployment and smoke testing
- Production connection and fixture verification
- Anthropic’s live production tool scan

The production catalogue contains 159 tools with no duplicate names.

### What do users need to do?

Existing custom-connector users should refresh or reconnect RED to receive the latest tool schemas and titles.

## RED 1.6.3 — Finalize application to Anthropic

**Released:** 26 August 2026

This release improves MCP compatibility, tool discoverability and metadata quality across supported AI platforms. This release prepares RED for review in Anthropic’s Claude Connector Directory while preserving all existing accounting workflows and safety controls.

### Improved MCP tool descriptions

All 159 production tools now publish concise, factual descriptions of their purpose, required inputs, outputs, effects and limitations.

Previous descriptions occasionally included conversational guidance or directions about when another tool should be used. These have been replaced with **neutral API-contract wording**, improving compatibility with MCP directory requirements and **making RED’s capabilities easier for AI clients to interpret**.

### Stronger description-policy validation

RED now applies a **fail-closed policy** whenever tools are registered. A tool cannot be published if its description contains:

- Instructions that attempt to control AI-model behaviour
- Directions to invoke or avoid another tool
- Conversational or answer-formatting instructions
- Hidden, encoded or non-printing text
- Other metadata that does not belong in a factual tool description

Descriptions are validated without silently deleting or rewriting their contents, making future metadata issues easier to detect during development.

### Updated help-tool metadata

The descriptions for RED’s Big Red Cloud help and resource-discovery tools have been simplified and made more factual. RED continues to provide:

- Big Red Cloud help articles
- Step-by-step product guidance
- Freshdesk resources
- BRC Edu and webinar content
- Screenshot-supported instructions
- Public support links

These help workflows remain read-only and can be used without connecting a company.

### Improved connector directory compatibility

RED’s production metadata has been verified through a live MCP tools/list exchange.

The production catalogue now confirms:

- 159 production tools
- 159 unique tool names
- **159 compliant, non-empty descriptions**
- Matching top-level and annotated titles
- Complete read-only, destructive and open-world safety annotations
- No hidden, encoded or behaviour related instructions in tool descriptions

This work supports RED’s application for inclusion in Anthropic’s Claude Connector Directory. The application is currently under review; directory availability remains subject to Anthropic’s approval.

### Existing safety controls remain unchanged

This release does not change RED’s accounting logic or posting behaviour.

RED continues to:

- Display previews before supported accounting writes
- Require explicit confirmation before posting
- Require additional confirmation for destructive and external actions
- Validate route tokens and company context
- Preserve counterparty and concurrency safeguards
- Scope accounting actions to connected companies
- Prevent RED from initiating real bank transfers or moving financial assets

### Customer impact

No customer action is required.

Existing RED connections and supported accounting workflows continue to operate as before.

### Quality assurance

RED 1.6.3 was validated through:

- Full application test coverage: 1,074 passed and 1 intentionally skipped
- Focused MCP registration and description-policy tests
- TypeScript type checking
- Production and staging MCP metadata audits
- Claude help, read-only and confirmation-boundary smoke tests
- Live verification of all 159 production tool descriptions

No accounting records were changed as part of the production metadata audit.
